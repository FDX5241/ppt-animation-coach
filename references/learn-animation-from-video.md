# 从新视频学习并开发 PPT 动画

这是一项独立的技术开发流程，用来从用户提供的新教程视频中学习尚未收录的 PPT 动画，并把验证成功的效果继续加入本项目。

## 适用场景

- 用户提供新的 PPT 教程视频，希望分析其中某一段动画
- 用户要求先理解原理，再制作演示
- 用户希望把验证成功的动画继续固化成新的 Skill 技术

如果用户调用的是已经实现的图片轮播、三条文字递进或分层视差，不需要重新分析教程视频，直接进入该技术的素材确认流程。

## 第一阶段：视频切片

1. 确认用户要研究的视频区间。用户给出大致时间时，可以向前、向后各多观察约 10 秒。
2. 使用 [scripts/extract-video-frames.py](../scripts/extract-video-frames.py) 按每秒一张图片导出切片。
3. 文件名必须包含相对于原视频的时间，例如 `frame-0210s.jpg`。
4. 保留连续切片，不要只挑几个看起来重要的画面。
5. 按时间顺序检查切片，记录界面操作、选择对象、图层变化、参数变化和最终播放效果。

示例：

```bash
python scripts/extract-video-frames.py tutorial.mp4 --output-dir work/frames --start 210 --end 280
```

## 第二阶段：语言拆解

在制作 PPT 前，先向用户提交完整的文字说明。至少包括：

- 动画最终看起来是什么样
- 一共有多少张幻灯片或关键状态
- 一共有多少种素材，每种素材需要多少个源文件
- 每个素材在每个状态中的位置、大小、旋转、透明度、裁剪、虚化和图层变化
- 哪些对象保持不动，哪些对象进入或退出画面
- 哪些页面必须由上一页整体复制
- 使用了平滑切换、普通动画还是两者组合
- 默认切换时间和自动换页方式
- 从现有步骤向后扩展时的递推规律

描述必须精确到“哪一个素材做了什么操作”。不要只写视觉感受，也不要在逻辑没有确认前制作演示。

## 第三阶段：素材准备与审批

1. 根据语言拆解生成素材清单，区分必需项和可选项。
2. 检查用户已有素材是否清晰、完整、可抠图、风格一致。
3. 对缺失素材提出明确的搜索或生成方案。
4. 搜索素材时记录来源和许可；生成素材时记录用途和提示要求。
5. 完成抠图、裁剪、比例统一、虚化或其他派生版本。
6. 把所有将进入 PPT 的候选素材展示给用户，包括会明显影响结果的派生版本。
7. 等待用户明确确认。未通过的素材单独修改并重新展示。

除非用户明确要求跳过预览，否则不得在素材确认前进入动画制作。

## 第四阶段：动画制作

1. 按已确认的状态表建立第一页全部对象。
2. 需要平滑对应关系时，复制整张幻灯片得到下一状态。
3. 只修改对应对象的属性，不重新插入或粘贴替代对象。
4. 使用稳定、可读的对象名称。
5. 在备注中记录步骤、参数、素材来源和兼容性提醒。
6. 导出静态预览检查构图和图层。
7. 导出动态预览检查节奏、对象对应和动画连续性。
8. 与教程切片对照，修正差异后交给用户审阅。

## 收录为新技术

用户确认演示效果后，才可以把它加入正式技术库。新增技术至少应包含：

- 独立参考文档
- 可复用构建脚本或明确的可复现步骤
- 一份可播放示例 PPT
- 静态或动态预览
- 技术索引记录
- 教程来源和研究区间
- 已知失败模式与兼容性说明
